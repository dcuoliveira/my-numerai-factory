## Main question
Do causal foundation-model representations (TabPFN v2, TimesFM, Chronos-2), merged as one 41-column feature_fm_ block, add incremental payout to any model on any base? Pre-run EDA expected TabPFN means to add partial IC +0.04 (t +2.6..3.6) over the fenccausal ridge.

## What was tried
The 9 representations of features-foundation.md built causally into one 41-column feature_fm_ block: TabPFN v2 on fenccausal (point preds, std/IQR/skew, 5 bin probabilities, estimator disagreement, 8 embedding PCs); TabPFN per block (tenc, interact, size, price, raw); 30/390-date context variants; TimesFM + Chronos-2 on each coin's log close <= D-1 (20-day q50/spread/skew) and 8 Chronos-2 embedding PCs. TabPFN context ends 20 dates before each 20-date refresh block; embedding bases fitted on a burn-in ending before the first training date; every column rank-binned per date. 3 bases × 5 models × {with, without}; without = same dataset with --feature-exclude '^feature_fm_'. 1,701-date spine to 2026-07-08, 510 scored periods. Paired Newey-West lag 20. Not live-wired.

## Trained parameters
From results/metrics/crypto/ridge/e109_ridge_fenc.json config (the "without" ridge/fenccausal arm): model ridge; data_version crypto/v2.0-fenccausal; cv_scheme rolling; train_window 130; refit_every 130; embargo 20; inner_cv purged; n_splits 5; val_frac 0.3; n_iter 50; search_type random; metric corr; target target_binned_return_20; n_features 44; seed 42; fixed_params null. CORR.mean 0.15175, MMC.mean 0.07105, n=510. The mlp_ktz/fenc twin is identical config with model mlp_ktz, CORR.mean 0.12946, MMC.mean 0.06311. The "_fm" arms are the same datasets without the exclude; the afpp base uses the 812-feature allfeat_pp data version.

## What was found
FINDINGS-BACKED. The block helps NO model on any base. Payout falls in all 15 with/without pairs and MMC in all 15; nothing rises. Payout Δ (with minus without, t): ridge raw −0.0178 (−2.33), ridge fenccausal −0.0170 (−2.35), ridge afpp −0.0012 (−0.41); lgb −0.0046/−0.0037/−0.0050; catboost −0.0038/−0.0060/−0.0043; rf −0.0053/−0.0026/−0.0044; mlp raw −0.0294 (−2.81), mlp fenc −0.0090, mlp afpp −0.0083. CORR rises in only 3 pairs (all |t|<1); CORR damage concentrated in ridge raw −0.028 (t −3.84), ridge fenc −0.028 (t −4.05), MLP raw −0.037 (t −3.46). Trees are flat (take the block, gain nothing); the linear ridge and the MLP give it weight and lose; on allfeat_pp's 853 columns the block is diluted. Why the prior failed: the causal TabPFN mean scores CORR 0.1095 on the 510 dates vs E19's 0.145 (per-date rank corr only 0.745, block-mean sd 0.082 over 27 refresh blocks) — each 20-date refresh draws a new 4,096-row context, so the column mean shifts within every training window, consistent with a fixed linear weight failing (a plausible, not tested, mechanism). This also makes E19's 0.145 look like a favourable 4-context draw (matters for TUPA_01). Checks: E19 replay reproduces to 2.9e-6; without-arms reproduce deployed backtests exactly (e109_rf_ktz_fenc = MA_FENC, e109_catboost_ktz_fenc = IAUARETE_01, e109_ridge_raw = CURUPIRA_02). Verdict: do not deploy. (E113 is the row ablation that locates the harm.)
