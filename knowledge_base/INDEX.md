# Experiment knowledge base — index

One entry per numbered study (E01–E127), distilled from `experiments/EXPERIMENTS.md`, the
project memory files and the metrics JSONs, so the raw row-level results could be removed.
Built 2026-10-24.

**How to read an entry:** Main question → What was tried → Trained parameters → What was found.
Each entry carries a **provenance** label saying how much to trust its finding:

| label | meaning | entries |
|---|---|---|
| FINDINGS-BACKED | a dedicated EXPERIMENTS.md section states the result | 33 |
| MEMORY-BACKED | only a project memory file states it | 25 |
| NUMBERS-ONLY | no written finding; summarised from the metrics JSONs | 63 |
| THIN | registered, but no finding and no usable numbers | 6 |

**Group files:** [`_diagnostics.md`](_diagnostics.md) — the torch walk-forward training-diagnostics
campaign (E104–E107 + the no-reg MLP investigation). [`_legacy_named_arms.md`](_legacy_named_arms.md)
— pre-numbering runs (`w6r6_*`, `xae_*`, `x3_*` LSTM, …), with which are production-protected.

**What was removed, and from where:** [`DELETION_LEDGER.md`](DELETION_LEDGER.md).

**The ground truth stays on disk.** Every removed forecast kept its `results/metrics/` config and
`results/per_period/` series, so CORR / MMC / payout per arm and per period can always be recomputed.
Payout everywhere here is **0.1·CORR + MMC** — never the metrics JSON's `pnl` field.

**Quality notes.** Every entry was adversarially checked against its sources; a sweep then corrected
pnl-mislabelled payouts in 26 entries and the arm rankings that depended on them. Entries the checkers
did not sample were swept only for that payout error, so treat an unsampled NUMBERS-ONLY ranking as a
lead to confirm against `results/metrics/`, not as a citation.
